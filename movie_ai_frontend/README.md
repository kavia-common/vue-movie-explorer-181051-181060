# Movie Explorer (Vue 3 + Vite)

This single‑page app provides an elegant, accessible movie browsing experience with a Royal Purple theme. It integrates Supabase for Google OAuth and real‑time CRUD on a per‑user movies table, and uses TMDB for search, trending, featured, and details. The app has two primary routes: a landing page at “/” and the application shell at “/app”.

## Prerequisites

Ensure you have a modern Node.js runtime and npm:
- Node.js 18+ recommended
- npm 9+ recommended

Install dependencies once your environment variables are set.

## Environment Setup

Create a `.env` file in `movie_ai_frontend` with the following variables. These are required for local development and production builds because Vite only exposes variables prefixed with `VITE_`.

```bash
VITE_SUPABASE_URL=your_supabase_project_url
VITE_SUPABASE_KEY=your_supabase_anon_public_key
VITE_TMDB_API_KEY=your_tmdb_v4_token_or_api_key
```

Notes:
- VITE_TMDB_API_KEY should be a valid TMDB credential. A TMDB v4 Read Access Token (Bearer) is recommended. Some endpoints can also accept the legacy v3 `api_key` query parameter; see the TMDB configuration section below for how this app handles both.
- If Supabase or TMDB variables are missing, the app will log a console warning and the related features will not function.

## Supabase Configuration

This app uses Supabase for authentication and real‑time database updates. You will configure the project URL, public (anon) key, Google OAuth, a `movies` table with RLS, and enable realtime.

### Project URL and Anon Key

- In the Supabase dashboard, copy your project URL and anon key (Project Settings → API).
- Set them as `VITE_SUPABASE_URL` and `VITE_SUPABASE_KEY` in `.env`.

### Google OAuth Provider

1. Enable the Google provider (Authentication → Providers → Google).
2. Provide Google OAuth client ID and secret.
3. Configure URLs:
   - Site URL: http://localhost:3000
   - Additional Redirect URLs:
     - http://localhost:3000/app
     - (Add your deployed production origin, plus its `/app` path)
4. Save changes.

The app initiates OAuth with:
- Redirect target after sign‑in: `window.location.origin + '/app'`
- You must include both the base site URL and the `/app` path in Supabase’s allowed URLs during development and in production.

### Database: Movies Table

Create a `movies` table that stores per‑user saved movies (one row per user/movie combination).

```sql
create table if not exists public.movies (
  id bigint generated by default as identity primary key,
  user_id uuid not null references auth.users (id) on delete cascade,
  title text not null,
  tmdb_id integer,
  poster_path text,
  created_at timestamptz not null default now()
);

-- Prevent duplicate saves of the same TMDB ID for a user.
-- Note: rows with NULL tmdb_id are considered distinct in a unique index.
create unique index if not exists movies_user_tmdb_unique
  on public.movies (user_id, tmdb_id);
```

### Row Level Security (RLS)

Enable RLS and add policies so users only see and modify their own rows.

```sql
alter table public.movies enable row level security;

-- Select: users read only their rows
create policy "Users can select their movies"
  on public.movies
  for select
  using (auth.uid() = user_id);

-- Insert: users insert only rows for themselves
create policy "Users can insert their movies"
  on public.movies
  for insert
  with check (auth.uid() = user_id);

-- Update: users update only their rows
create policy "Users can update their movies"
  on public.movies
  for update
  using (auth.uid() = user_id)
  with check (auth.uid() = user_id);

-- Delete: users delete only their rows
create policy "Users can delete their movies"
  on public.movies
  for delete
  using (auth.uid() = user_id);
```

### Realtime

The app subscribes to realtime events on `public.movies` filtered by the current user. Ensure the table is enabled for replication in Realtime (Database → Replication → Realtime) for the `movies` table in the `public` schema.

## Routes and Auth Flow

- “/” (Landing): Marketing/intro experience with a transparent Navbar and call‑to‑action. You can initiate Google sign‑in here.
- “/app” (App Shell): Auth‑aware experience with TMDB search, Trending/Featured, and Your Movies. After sign‑in, Supabase redirects back to this route.

On first sign‑in, you should be redirected to `/app`. Ensure this path is configured in Supabase OAuth Additional Redirect URLs.

## TMDB Configuration and Usage

All TMDB access is centralized in `src/services/tmdb.ts`. The app uses a single configuration object and always sends a Bearer token via the `Authorization` header. For specific endpoints that require an `api_key` query parameter, the app appends it as instructed by the integration pattern.

Centralized configuration:

```ts
// src/services/tmdb.ts (excerpt)
export const TMDB_CONFIG = {
  BASE_URL: 'https://api.themoviedb.org/3',
  API_KEY: import.meta.env.VITE_TMDB_API_KEY as string,
  headers: {
    accept: 'application/json',
    Authorization: `Bearer ${import.meta.env.VITE_TMDB_API_KEY as string}`,
  } as HeadersInit,
} as const
```

Requests are made through a shared helper that sets headers and throws detailed errors on failure. Public functions include:
- searchMovies(query: string) → GET /search/movie
- getTrending() → GET /trending/movie/week
- getFeatured() → GET /movie/top_rated
- fetchMovieDetails(id: number) → GET /movie/{id} with `api_key` appended in addition to Bearer auth

If `VITE_TMDB_API_KEY` is not set, the app logs a warning and TMDB features are disabled.

## Supabase Integration Details

- Client initialization: `src/lib/supabaseClient.ts` reads `VITE_SUPABASE_URL` and `VITE_SUPABASE_KEY` and enables session persistence and auto‑refresh.
- Session management: `src/stores/session.ts` listens for auth changes and exposes `signInWithGoogle()` and `signOut()` actions. OAuth uses `redirectTo: window.location.origin + '/app'`.
- Movies store: `src/stores/movies.ts` implements per‑user CRUD on the `movies` table, deduplicates writes by TMDB ID, and subscribes to realtime changes filtered by the authenticated user.

## Royal Purple Theme and Accessibility

The interface follows an elegant Royal Purple theme configured in `tailwind.config.js`. Primary UI elements use `#8B5CF6` with warm gray accents, and surfaces are kept light for a refined, luxurious feel. Backgrounds employ subtle gradients to produce depth and polish.

Accessibility is addressed through semantic roles, ARIA labeling on interactive elements, and visible focus states. The stylesheet includes a reusable `focus-ring` utility class that applies prominent focus outlines for keyboard navigation. Components provide alt text on images, aria‑labels on buttons, and live regions where appropriate. The layout is responsive and adapts gracefully across viewport sizes.

## Troubleshooting

- Missing environment variables: The app logs console warnings if Supabase or TMDB variables are not set. Ensure `.env` includes all required variables and restart the dev server after changes.
- OAuth redirect issues: If sign‑in loops or fails, confirm that both http://localhost:3000 and http://localhost:3000/app are in Supabase’s allowed URLs and that your Google credentials are correct.
- Realtime not updating: Verify the `movies` table is enabled for Realtime replication and that RLS policies allow the authenticated user to read their own rows.
